> 上图是**运行时架构**，`tests/` 不出现在图中是因为它不参与运行时——它是一套独立构建的 Google Test 可执行文件（`azur_agent_tests`），直接编译 `core/`、`data/` 下的被测源文件，对图中 `ToolExecutor`、`ContextPolicy`、`AppSettings` 等纯逻辑模块做单元测试验证。测试覆盖范围与已知缺口见「文件详解 → 测试模块」。

> **历史上这里是双模式架构**：Chat 和 Project 两个页面共用同一个 `AgentEngine` 实例，靠 `ModeManager` 做模式切换、靠 `engine->isBusy()` 互斥检查防止互相打断，`ToolExecutor` 也曾包含 `write_file`/`apply_patch`/`run_command`/Git 工具等写操作能力（配合 `ConfirmDialogs` 做确认弹窗）。项目重心转向"和企业聊天"之后，这套双模式共享引擎的设计连同 Project 相关模块一起被移除——不再有互斥抢占问题，因为现在从始至终只有一个页面在用这个引擎。工具集也收窄成 `read_file`/`list_directory` 两个只读工具，不再需要写操作确认机制。
