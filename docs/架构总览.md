> 上图是**运行时架构**，`tests/` 不出现在图中是因为它不参与运行时——它是一套独立构建的 Google Test 可执行文件（`azur_agent_tests`），直接编译 `core/`、`data/` 下的被测源文件，对图中 `ToolExecutor`、`ContextPolicy`、`AppSettings` 等纯逻辑模块做单元测试验证。测试覆盖范围与已知缺口见「文件详解 → 测试模块」。

> **关于工具执行**：`ToolExecutor` 默认走 Python 后端（主程序在 `main.cpp` 里 `setUsePythonBackend(true)`），即上面图里的 `QProcess` → `cli.py` 这条线；后端基础设施故障时自动回退到 C++ 原生实现（图里 ToolExecutor 节点本身），两者行为一致。Python 侧代码见 `python/azur_tools/`，设计取舍见「关键设计决策 → 7」。

> **历史上这里是双模式架构**：Chat 和 Project 两个页面共用同一个 `AgentEngine` 实例，靠 `ModeManager` 做模式切换、靠 `engine->isBusy()` 互斥检查防止互相打断，`ToolExecutor` 也曾包含 `write_file`/`apply_patch`/`run_command`/Git 工具等写操作能力（配合 `ConfirmDialogs` 做确认弹窗）。项目重心转向"和企业聊天"之后，这套双模式共享引擎的设计连同 Project 相关模块一起被移除——不再有互斥抢占问题，因为现在从始至终只有一个页面在用这个引擎。工具集也收窄成 `read_file`/`list_directory` 两个只读工具，不再需要写操作确认机制。

> **语气一致性（P1）**：`MainWindow::buildPostHistoryInstructions()` 调 `PromptLoader::buildPostHistoryInstructions(style)`（style 来自 `AppSettings::chatPromptMode()`，读 `full/` 或 `lite/` 的 `enterprise_instructions.md`），产物作为 `AgentEngine::start()` 的第 8 个参数传入。`AgentEngine::sendRequest()` 在组装好消息列表之后、真正发请求之前注入：**云端模型**追加一条尾部 `{role:"system"}` 消息；**本地模型**把指令拼到最后一条 user 消息内容后面（用 `\n\n---\n\n` 分隔）。这条指令离生成点最近，是对「崩人设」最有效的抑制。指令为空时跳过注入，行为与旧版完全一致。

> **语音朗读（P2）**：回复完成后 `MainWindow::onApiResponseCompleted()` 里若开启语音（`AppSettings::ttsEnabled()`），`TtsClient::synthesize()` 用 QProcess 异步调 `python/azur_tools/tts_cli.py`（stdin/stdout JSON 协议，同工具后端 `cli.py` 的通道），脚本内部用 edge-tts 合成 mp3 存到 `AppDataLocation/tts_cache/`，完成后发 `synthesized(path)` 信号，`MainWindow` 里的 `QMediaPlayer` + `QAudioOutput` 播放。TtsClient 不阻塞 UI：全程信号槽异步、带 30s 超时 kill、失败只 qWarning 不弹窗；合成前会清理旧文件限制缓存大小。

> **事实记忆（P3）**：设置页勾选「事实记忆」（`AppSettings::memoryEnabled()`，默认关）后，每轮回复完成 `MainWindow::onApiResponseCompleted()` 会触发 `MemoryClient::updateMemory()`，QProcess 异步调 `python/azur_tools/memory_cli.py`（stdin/stdout JSON 协议，只依赖 urllib 标准库），脚本内用 LLM 对最近对话做结构化抽取，输出 `{"facts":[{"key","value","confidence"}]}`。C++ 侧 `MemoryClient::mergeFacts()` 做同 key 去重（新值覆盖旧值）+ `QSaveFile` 原子写回 `AppDataLocation/memory/facts.json` + `memory/backups/` 备份（最多 5 份）。注入侧：`MainWindow::buildContextInstructions()` 每次发送前现算，读 facts.json 渲染成 `[记忆] ...` 片段并进 P1 的 post-history 指令（上限 30 条 / 800 字符），走 `AgentEngine::start()` 第 8 个参数同一注入点。合并/渲染是纯函数，`tests/test_memory_client.cpp` 直接覆盖。
