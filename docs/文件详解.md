## 文件详解

### 入口层

#### `app/main.cpp` (70 行)

程序入口。职责：

1. **日志钩子** — 将所有 `qDebug()`/`qWarning()` 输出重定向到 `daily_log/azur_debug_YYYY-MM-DD.log`
2. **ElaApplication 初始化** — ElaWidgetTools 库的要求
3. **创建并显示 MainWindow**

### UI 主框架

#### `mainwindow.h/.cpp` (约 550 行)

核心 UI 框架，继承 `ElaWindow`。负责导航栏/AppBar 搭建、聊天发送逻辑。

**导航管理：**
- 3 个页面节点：对话、设置、关于
- 通过 `addPageNode()` / `addFooterNode()` 构建侧边导航

**发送流程（`onSendClicked`）会依次检查：**
1. API Key 是否已填写
2. Base URL 是否是合法的 http(s) 地址
3. 模型名称是否已填写
4. 追加消息 → `chatEngine_->start(...)`

**AppBar 右侧按钮区：**
- `sidebarToggleBtn_` — 折叠左侧历史记录面板

**关键依赖：**
```
MainWindow
├── ChatPageWidget         (聊天页面)
├── SettingPageWidget      (设置页面)
├── AgentEngine            (AI 引擎)
├── ConversationManager    (对话持久化)
└── DeepSeekClient         (API 客户端)
```

### Agent 引擎与工具执行

#### `agent_engine.h/.cpp` (约 210 行)

Agent 循环核心，封装了"请求 AI → 解析工具调用 → 执行工具 → 再次请求"的完整循环。

**核心流程：**
```
start() ──→ sendRequest() ──→ AI 返回流式文本
                                    │
                                    ├── 纯文本 → onResponseCompleted() → doFinish()
                                    │
                                    └── tool_calls → onToolCallsReceived()
                                          │
                                    executeToolCalls()
                                          │
                                    toolRound_++
                                          │
                                    sendRequest()
```

> 当前工具集里只有 `read_file`/`list_directory` 两个只读工具，`onToolCallsReceived()` 收到工具调用后会直接执行，不存在需要用户确认的分支。不过 `MainWindow` 目前传给 `start()` 的 `tools` 参数恒为空数组，这条工具调用路径实际上还没有被触发过——保留着是为了以后如果想让企业读取聊天中提到的文件，可以直接把 `ToolExecutor::toolDefinitions()` 和真实的 `workspaceRoot` 传进去复用。

**关键成员：**
- `messageHistory_` — 完整消息历史（含 tool 消息）
- `toolRound_` / `maxToolRounds_` — 防止无限循环（默认上限 200 轮）
- `isBusy()` — 目前就是 `isRunning_`

**信号：**
| 信号 | 触发时机 |
|------|----------|
| `chunkReceived(delta)` | 流式文本片段 |
| `stepChanged(text)` | 步骤状态变化 |
| `finished(fullText)` | 循环正常结束 |
| `errorOccurred(msg)` | 错误终止 |


#### `ai_client.h/.cpp` (约 320 行)

AI API 客户端，负责与 OpenAI/DeepSeek 兼容接口通信。

**SSE 流式处理关键设计：**
- `sseLineBuffer_` — 持久化缓冲区，处理网络分包导致的不完整行（一条 `data: {...}` 可能被拆成两次 `readyRead()`）
- `PendingToolCall` — 按 `index` 累积拼接工具调用分片（`arguments` 是分段 JSON 字符串）
- `sawToolCallFinish_` — 检测 `finish_reason: "tool_calls"`
- **兜底逻辑** — 非流式响应也兼容处理

#### `tool_executor.h/.cpp` (约 260 行)

工具执行器，目前只有两个只读工具。

**两个工具：**
| 工具 | 功能 | 安全限制 |
|------|------|----------|
| `read_file` | 读取文本文件内容 | ≤300KB，跳过二进制，路径限制在工作区内 |
| `list_directory` | 列出目录内容 | ≤200 条，路径限制在工作区内 |

**安全设计：**
- `resolveSafePath()` — 路径穿越防护，用 `canonicalFilePath()` + `relativeFilePath()` 判断目标是否越出工作区目录，而不是简单的字符串前缀比较（能防住 `../` 拼接、跨盘符等常见绕过手法）
- `setAllowedPaths()` — 额外的路径白名单，工作区目录之外但被显式允许访问的路径
- `isWriteTool()` — 保留这个函数只是为了不用改 `AgentEngine` 的调用接口，实际恒返回 `false`


#### `contextpolicy.h/.cpp` (约 420 行)

轻量级上下文裁剪策略类。**纯策略，不维护任何状态**，输入 `AgentEngine` 的消息历史，输出裁剪后的副本。

**核心函数：**
- `trim(messages, maxMessages, maxToolResults, maxTotalSize, protectedTurns, report)` — 静态函数，执行多阶段裁剪

**裁剪策略：**
1. **system 消息永久保护**，永不丢弃
2. **最近的 N 轮对话**（user/assistant）受年龄保护（`protectedTurns` 参数控制，默认 15 轮）
3. **tool 消息分级**：写操作/错误结果 = 高价值，命令执行 = 中价值，读操作 = 低价值（优先丢弃）——这套分级是为十个工具的年代设计的，现在只剩两个只读工具，分级策略可以考虑简化
4. **tool call 完整性保护**：如果 assistant（含 tool_calls）被保留，它所有的 tool 结果也必须保留，否则 API 会拒绝请求

**诊断报告：**
`ContextReport` 结构体记录裁剪前后的数量/大小/分类统计，供日志和 UI 展示。

这个类目前被 `AgentEngine` 在每次 `sendRequest()` 时调用，防止 token 预算爆炸。

### 共用工具模块 ★

这些文件不承载独立业务逻辑，是为了消除重复代码单独抽出来的，**改跨模块共用的东西，先看这里有没有现成的，别急着复制粘贴**。

#### `ui/uiconstants.h`

目前只有一个常量：`UiConstants::kSpinnerFrames`，Agent"思考中/执行中"用的旋转动画帧（盲文字符）。`chatpagewidget.cpp` / `messagebubblewidget.cpp` 都引用它。C++17 inline 变量，直接在头文件里定义，多个 .cpp 包含不会报重复定义。

#### `appsettings.h/.cpp` (约 45 行)

**全项目唯一允许出现 `QSettings("AzurStudio", "AzurAgent")` 构造调用的文件**（在 `appsettings.cpp` 内部）。所有配置项的读写都通过 `AppSettings::xxx()` 静态函数完成，一眼能看到项目一共有哪些配置：

| 函数 | 对应设置 | 默认值 |
|------|----------|--------|
| `apiKey()` / `setApiKey()` | API Key | 空 |
| `baseUrl()` / `setBaseUrl()` | Base URL | `https://api.deepseek.com` |
| `model()` / `setModel()` | 模型名称 | `deepseek-v4-flash` |
| `recentModels()` / `setRecentModels()` | 最近使用的模型列表 | 空 |
| `chatPromptMode()` / `setChatPromptMode()` | 人格模式：0=精简（本地模型推荐），1=完整（云端模型推荐） | 0 |
| `bgOpacity()` / `setBgOpacity()` | 聊天背景透明度 | 25 |
| `chatBgEnabled()` / `setChatBgEnabled()` | 显示聊天背景（开关，默认关，未启用时透明度无效） | false |
| `showStatusBar()` / `setShowStatusBar()` | 显示底部状态栏 | `true` |

**新增一个配置项**：在 `appsettings.h` 加一对声明、在 `appsettings.cpp` 加一对实现，不要在业务代码里直接 `new QSettings(...)`。

### 其它 UI 组件

#### `conversationview.h/.cpp` (约 400 行)

聊天消息展示区域的实现：消息气泡列表 + 输入框 + 发送/停止按钮 + 流式内容节流刷新。

由 `ChatPageWidget` 持有。历史上这个组件是为了消除 Chat/Project 两个页面各写一份几乎一致的 `appendMessage`/`clearChatDisplay`/`onChunkReceived`/`flushAiContent`/`setInputEnabled` 等实现而抽出来的共享组件（`ProjectPage` 已移除，现在是唯一的调用方，但保留"只负责展示，不知道业务逻辑"的设计原则，方便以后再拆分调用方）。

**设计原则：** 这个组件只负责"展示"，不知道 `AgentEngine`。发送按钮/回车键只会发出 `sendRequested` 信号，是否真的调用 `AgentEngine`、回复完成后要做什么业务逻辑（比如自动生成标题、同步消息历史），都由 `ChatPageWidget` 决定。

**关键特性：**
- 流式输出 50ms 节流定时器，避免逐 token 触发重排版
- 自适应滚动到底部
- `flushPendingContent()` — 停止节流并立即刷新，确保回复/错误时不会丢最后一小段
- 底部状态栏：显示当前模型名与实时时间，可通过设置开关显隐
- 发出 `viewportResized` / `firstChunkOfResponse` 信号供外层做背景适配和步骤指示器更新

#### `messagebubblewidget.h/.cpp` (约 350 行)

消息气泡组件，同时支持用户消息和 AI 消息。AI 消息走 Markdown 渲染（代码块带"复制"按钮 + 红绿灯装饰），支持流式内容实时更新。

#### `markdownrenderer.h/.cpp`

轻量级 Markdown → HTML 转换器：代码块、行内代码、加粗/斜体、链接、Diff 语法高亮。

- 代码块采用浅色背景（`#f6f8fa`）+ 灰色头部，类似 GitHub 风格
- 行内代码用浅灰底深灰字
- Diff 语法高亮：`+` 行绿色、`-` 行红色

#### `settingpagewidget.h/.cpp`

设置页面，采用卡片式布局（`QFrame` 圆角卡片），分为两个分组：
- **AI 服务连接**：API Key / Base URL / 模型名称
- **对话设置**：Prompt 模式（精简 / 完整）
- **界面与外观**：显示聊天背景开关（默认关）/ 聊天背景透明度 / 底部状态栏显隐开关

**本身不直接持有配置状态**，所有读写都转发给 `AppSettings`。

### 数据管理层

#### `conversationmanager.h/.cpp` (约 245 行)

对话持久化管理器，存储在 `{AppData}/AzurAgent/data/`（`conversations.json` 元信息 + `chats/*.json` 消息内容）。

#### `promptloader.h/.cpp` (约 45 行)

- `buildFullPersonaPrompt()` — 拼接 `resources/full/` 下的 `enterprise_personality.md` + `enterprise_quotes.md` 成完整 system prompt。
- `buildChatSystemPrompt(style)` — style=1 完整版（同上），style=0 精简版（`resources/lite/enterprise.md`），由设置项 `chatPromptMode` 控制。

> `loadFile()` 先读 `RESOURCES_DIR`（编译时写死的源码树绝对路径，开发时用），失败了退到 `app.qrc` 打包进二进制的内容（分发后用）。两条路径请求的是同一个相对文件名，`app.qrc` 里的 `<file alias="...">` 必须带上同样的 `full/`/`lite/` 前缀，否则 qrc 兜底会静默失效——这是这一轮清理时顺手修的一个真实 bug，此前打包分发到别的机器后人格设定会直接丢失且没有任何弹窗提示。

### 测试模块

`tests/` 目录使用 Google Test（`FetchContent` 拉取 v1.14.0），通过 `tests/CMakeLists.txt` 独立构建成 `azur_agent_tests` 可执行文件，由根 `CMakeLists.txt` 的 `enable_testing()` + `add_subdirectory(tests)` 接入 CTest（`ctest` 或 IDE 的"运行测试"均可触发）。

**当前覆盖 3 个模块：**

| 测试文件 | 覆盖的源文件 | 重点覆盖内容 |
|------|------|------|
| `test_tool_executor.cpp` | `core/tool_executor.cpp` | `resolveSafePath()` 路径穿越防护（越界拒绝/白名单放行）、`read_file`/`list_directory` 的成功与失败路径、`isWriteTool()` 恒为 false、`toolDefinitions()` 只暴露两个只读工具 |
| `test_context_policy.cpp` | `core/contextpolicy.cpp` | system 消息永不丢弃、最近 N 轮保护、tool 消息分级丢弃、tool_calls 与其 tool 结果的完整性绑定、空输入/极端参数不崩溃 |
| `test_appsettings.cpp` | `data/appsettings.cpp` | 各配置项默认值、读写往返（round-trip），验证「全项目唯一 QSettings 入口」没有读写不对称的问题 |

**测试构建方式：**
`tests/CMakeLists.txt` 里的 `TEST_SOURCES` 直接把被测源文件（`../core/tool_executor.cpp` 等）编译进测试可执行文件，而不是链接主程序产物——这意味着测试和主程序是两份独立编译产物，**改被测函数签名后要同时确认测试目标能编译过**，本地跑一遍 `azur_agent_tests` 是唯一保证。

**尚未覆盖的模块：** `agent_engine.cpp`（Agent 循环、`isBusy()` 状态机）、`ai_client.cpp`（SSE 流式解析）、`promptloader.cpp`，以及所有 UI 层组件都还没有单元测试，目前只能靠手工验证。`agent_engine` 和 `ai_client` 涉及网络/异步信号槽，补测试的成本比纯函数类（`tool_executor`/`contextpolicy`）高一些，是后续测试建设的主要缺口。

**已移除的测试：** 原来还有 `test_git_executor.cpp`（覆盖已删除的 `git_executor.cpp`）和一个孤立、未参与实际构建的 `tests/contextpolicy.cpp`（`core/contextpolicy.cpp` 的旧版拷贝），随 Git 工具移除和文档清理一并删掉了。
