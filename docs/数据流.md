## 数据流

### 发送一条消息

```
用户输入
  ▼
MainWindow::onSendClicked()
  │ API Key / Base URL / 模型名称检查
  │ messageHistory_.append(userMsg)
  ▼
AgentEngine::start(apiKey, baseUrl, model, messageHistory, systemPrompt, tools=[], workspaceRoot="")
  │
  ├── sendRequest() → DeepSeekClient::sendMessage() → AI 流式返回
  │     ├── chunkReceived(delta) → onApiChunkReceived() → ChatPageWidget::onChunkReceived()
  │     └── responseCompleted(fullText) → onApiResponseCompleted() → ConversationManager::saveConversation()
  │
  └── tools 恒为空数组，AI 不会发起工具调用，onToolCallsReceived() 这条分支实际不会触发
```

> `AgentEngine` 内部仍然保留 `onToolCallsReceived()` / `executeToolCalls()` 这套工具调用处理逻辑（对应 `ToolExecutor` 的 `read_file`/`list_directory` 两个只读工具），但目前 `MainWindow` 传给 `start()` 的 `tools` 参数始终是空的 `QJsonArray()`，所以这条路径当前处于"代码还在，但没有触发条件"的状态。如果以后想让企业能够读取你聊天时提到的某个文件，把 `ToolExecutor::toolDefinitions()` 传进 `tools` 参数、把 `workspaceRoot` 换成真实路径即可复用。

> 历史上这里还有一条完整的「Project 模式」数据流：打开项目 → `ModeManager` 初始化 → 索引构建 → 发送消息时经过 `engine_->isBusy()` 互斥检查 → 工具调用如果涉及写操作会走 `previewDiff()` → `ConfirmDialogs` 确认弹窗 → 用户确认/拒绝两条分支。随着 Project 模式、写操作工具、确认弹窗机制一起被移除，这条数据流已经不存在了。
