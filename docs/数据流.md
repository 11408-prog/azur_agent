## 数据流

### 发送一条消息

```
用户输入
  ▼
MainWindow::onSendClicked()
  │ API Key / Base URL / 模型名称检查
  │ messageHistory_.append(userMsg)
  ▼
AgentEngine::start(apiKey, baseUrl, model, messageHistory, systemPrompt,
                   tools=[], workspaceRoot="", postHistoryInstructions)
  │
  ├── sendRequest()
  │     ├── 组装好消息列表后：postHistoryInstructions 非空时注入
  │     │     ├── 云端模型 → 追加尾部 {role:"system"} 消息（离生成点最近）
  │     │     └── 本地模型 → 拼到最后一条 user 消息内容后（\n\n---\n\n 分隔）
  │     └── DeepSeekClient::sendMessage() → AI 流式返回
  │           ├── chunkReceived(delta) → onApiChunkReceived() → ChatPageWidget::onChunkReceived()
  │           └── responseCompleted(fullText) → onApiResponseCompleted()
  │                 ├── ConversationManager::saveConversation()
  │                 └── AppSettings::ttsEnabled() → TtsClient::synthesize(text, voice)
  │                       └── QProcess → tts_cli.py → edge-tts 合成 mp3 → synthesized(path)
  │                             → QMediaPlayer + QAudioOutput 播放
  │
  └── tools 恒为空数组，AI 不会发起工具调用，onToolCallsReceived() 这条分支实际不会触发
```

> **语气约束注入点**：`postHistoryInstructions` 由 `MainWindow::buildPostHistoryInstructions()` 提供（读 `full/` 或 `lite/` 的 `enterprise_instructions.md`），在**历史之后、生成之前**注入——这是对语气一致性影响最大的位置。传空字符串则跳过注入，行为与旧版完全一致，见「关键设计决策 → 8」。

> `AgentEngine` 内部仍然保留 `onToolCallsReceived()` / `executeToolCalls()` 这套工具调用处理逻辑（对应 `ToolExecutor` 的 `read_file`/`list_directory` 两个只读工具），但目前 `MainWindow` 传给 `start()` 的 `tools` 参数始终是空的 `QJsonArray()`，所以这条路径当前处于"代码还在，但没有触发条件"的状态。如果以后想让企业能够读取你聊天时提到的某个文件，把 `ToolExecutor::toolDefinitions()` 传进 `tools` 参数、把 `workspaceRoot` 换成真实路径即可复用。

> **工具执行本身的分流**：`ToolExecutor::execute()` 默认走 Python 后端——`QProcess` 拉起 `azur_agent/Scripts/python.exe` 执行 `python/azur_tools/cli.py`（stdio JSON 协议），`cli.py` 内部调 `executor.py` 完成真正的读取/列目录；后端基础设施故障时自动回退 C++ 原生实现。两侧行为一致，见「关键设计决策 → 7」。

> 历史上这里还有一条完整的「Project 模式」数据流：打开项目 → `ModeManager` 初始化 → 索引构建 → 发送消息时经过 `engine_->isBusy()` 互斥检查 → 工具调用如果涉及写操作会走 `previewDiff()` → `ConfirmDialogs` 确认弹窗 → 用户确认/拒绝两条分支。随着 Project 模式、写操作工具、确认弹窗机制一起被移除，这条数据流已经不存在了。
