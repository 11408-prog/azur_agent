## 构建与运行

### 依赖

- Qt 6.5+（Core, Widgets, Network, Multimedia）
  - **Multimedia** 只用于语音朗读（`QMediaPlayer`/`QAudioOutput` 播放 edge-tts 合成的 mp3）。如果不想用语音朗读，可以接受没有它时播放功能失效——但主程序会因链接失败编不出来，所以 Multimedia 是编译期必需组件。
- ElaWidgetTools（ 没有预编译，如果使用的话需要编译一下并将生成物创建一个`lib/`文件夹并放入,如果不确定位置可以看CMakeList）
- CMake 3.19+
- MinGW 或其他 C++17 编译器
- Python 3（可选，跑工具后端用）：需要在项目根建一个名为 `azur_agent` 的虚拟环境
  ```
  python -m venv azur_agent
  ```
  虚拟环境不建也能跑，工具调用会自动回退到 C++ 原生实现（见「关键设计决策 → 7」）。
- edge-tts（可选，语音朗读用）：装进 `azur_agent` 虚拟环境，**运行时需联网**（微软在线合成）
  ```
  azur_agent/Scripts/python.exe -m pip install edge-tts
  ```
  没装也能跑，只是设置页勾了「语音朗读」后合成会失败（失败只写日志不弹窗）。TTS 脚本 `python/azur_tools/tts_cli.py` 内部在真正合成前才 `import edge_tts`，因此协议测试（`test_tts_client.cpp`）不需要这个包也能跑。
- 事实记忆（`python/azur_tools/memory_cli.py`）**不需要额外 pip 包**——只用 urllib 标准库调 LLM，设置页勾「事实记忆」即可使用（默认关闭）。

### VSCode 集成（Qt + CMake Tools）

本机环境：Qt `6.11.1/mingw_64` + Qt 官方安装器自带的 MinGW `13.1.0` + Ninja，路径固定为 `C:/Qt/...`。机器上若同时装了 MSVC（Visual Studio），CMake Tools 会默认优先选 MSVC kit——但它编不了 `mingw_64` 版 Qt，**这是 VSCode 集成最常见的失败原因**。

#### 需要的扩展

- **C/C++**（`ms-vscode.cpptools`）：编译、调试、智能提示
- **CMake Tools**（`ms-vscode.cmake-tools`）：配置 / 构建 / 选 preset
- **CMake**（`twxs.cmake`）：语法高亮（可选）
- **vscode-qt**（`qtsupport`，可选）：`.ui` / `.qrc` 编辑、natvis 调试可视化

#### 仓库内已配好的文件

| 文件 | 作用 |
|---|---|
| `CMakePresets.json` | 锁定编译器（MinGW 13.1）+ Qt 前缀（`CMAKE_PREFIX_PATH`）+ Ninja，绕开 CMake Tools 的 kit 自动选择；构建目录 `build-vscode/` 与命令行 `build/` 隔离；开启 `CMAKE_EXPORT_COMPILE_COMMANDS` 供智能提示用 |
| `.vscode/settings.json` | 让 CMake Tools 强制走 preset；集成终端自动带上 Qt / MinGW / ElaWidgetTools 的 PATH |
| `.vscode/c_cpp_properties.json` | 未构建时也有智能提示（编译器 + Qt 各模块 include 路径） |
| `.vscode/launch.json` | F5 用 gdb 调试，启动时自动带 Qt DLL / 插件（`QT_PLUGIN_PATH`）/ ElaWidgetTools 的 PATH |

> 这四个文件已被 `.gitignore` 忽略（机器相关路径，不应进仓库）。换机器时只需改 `CMakePresets.json` 里的编译器路径与 `CMAKE_PREFIX_PATH` 三处。

#### 使用步骤

1. 用 VSCode 打开项目根文件夹。
2. 等 CMake Tools 在底部状态栏出现；若显示 `No Preset Selected`，点它 → 选 `MinGW 13.1.0 · Qt 6.11.1 (Debug)`（或 `Ctrl+Shift+P` → `CMake: Select Configure Preset`）。
3. **构建**：`Ctrl+Shift+B`（首次较慢，之后 Ninja 增量很快）。
4. **调试**：`F5`（断点、变量、调用栈正常；gdb 已配 pretty-printing）。
5. **跑单元测试**：把 `CMakePresets.json` 里 `AZUR_BUILD_TESTS` 改成 `ON` 重新配置，再用 VSCode 测试面板或 `cmake --test --preset mingw-debug`。

#### 常见坑

- **误选 MSVC kit**：报错形如「无法找到 Qt6 / `Qt6Config.cmake`」。解决：确认状态栏选的是 `mingw-debug` preset（它显式指定了 MinGW 编译器）。
- **GUI 程序在终端里「没反应」**：`agent_.exe` 是 WIN32 GUI 程序，控制台敲完立刻返回提示符是正常的，窗口独立弹出。直接双击或在 VSCode 里 F5 都行。
- **普通 cmd 跑 exe 报「找不到 Qt6Core.dll」**：需先把 `C:\Qt\6.11.1\mingw_64\bin`、MinGW 的 `bin`、`<项目>\lib\ElaWidgetTools\bin` 加进 `PATH`（VSCode 集成终端已自动配好）。

### 构建单元测试

单元测试默认关闭（避免默认构建拉取 GoogleTest）。需要跑测试时打开开关：

```bash
cmake .. -DAZUR_BUILD_TESTS=ON
cmake --build . --target azur_agent_tests
./azur_agent_tests
```

在 Qt Creator 里：项目设置 → CMake 配置 → 把 `AZUR_BUILD_TESTS` 设为 `ON`，重新配置后构建列表里会出现 `azur_agent_tests` 目标。

GoogleTest 首次会通过 FetchContent 从 GitHub 下载；下载过之后缓存在 `build/*/_deps/` 里，之后离线也能构建。测试可执行文件依赖 Qt 运行库，命令行直接跑前需要把 Qt 的 bin 目录加进 `PATH`（Qt Creator 里运行会自动处理好）。
