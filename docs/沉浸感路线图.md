# 沉浸感路线图

> **本文件是设计记录，标注为「暂不实现」的部分只是把设计写清楚，防止以后做的时候重新想。
> 当前只实现了 P1（语气一致性）和 P2（语音朗读）。**

## 已实现

- **P1 语气一致性**：`buildPostHistoryInstructions()`（`core/promptloader`）生成「历史之后」的语气约束指令，`AgentEngine` 在云端模型上追加尾部 system 消息、在本地模型上拼到最后一条消息，防止对话变长后人设漂移。
- **P2 语音朗读**：`python/azur_tools/tts_cli.py` + `core/ttsclient`（QProcess 异步调用 edge-tts），回复完成后自动合成 mp3 并播放。

## P3 记忆（事实记忆）—— 设计记录，暂不实现

### 目标

让「企业」在跨会话、长对话里记住用户说过的重要事实（名字、偏好、约定、港区日常细节），避免每轮都像第一次认识一样。

### 设计

1. **事实抽取**：每轮对话结束后，用 LLM 对「本轮 user + assistant」做一次结构化抽取，输出 JSON：
   ```json
   {
     "facts": [
       {"key": "user_name", "value": "小明", "source_turn": 12, "confidence": 0.9},
       {"key": "preference_tea", "value": "喜欢龙井", "source_turn": 13, "confidence": 0.7}
     ]
   }
   ```
   存成 `AppDataLocation/memory/facts.json`（追加式，带去重：同 key 新值覆盖旧值）。

2. **注入**：每次请求前，把与当前对话相关的事实压缩成一小段，注入到 system prompt 里（或并入 P1 的 post-history 指令）：
   ```
   [记忆] 用户叫小明；喜欢龙井；上周说过在准备面试。
   ```

3. **可选向量检索**：对话足够长、事实条目足够多之后，纯 key 匹配不够用。可引入：
   - `sqlite-vec` 存 embedding 向量，按语义相似度召回相关事实，而不是全部塞进 prompt（省 token、防「事实堆砌」淹没人格）。
   - 本地 embedding 用 `bge-small-zh`（中文效果好、体积小）。

### 待定项

- **embedding 来源**：DeepSeek 没有 embedding API，所以要么本地跑 `bge-small-zh`（需要 ONNX/runtime 依赖，跨平台部署成本高），要么换一家有 embedding API 的服务商。这是 P3 里最大的未知数，先不拍板。

### 不做什么（当前）

- 不自动把对话历史整段塞进记忆文件——只存抽取出的「事实」，避免记忆膨胀和隐私负担。

## P4 故事连续性（lorebook + 故事状态）—— 设计记录，暂不实现

### 目标

让角色扮演有「世界感」和「剧情推进」：关键设定/世界观能按关键词触发，当前剧情位置、地点、事件能被记住，对话像是发生在同一个连贯世界里。

### 设计

1. **Lorebook（关键词触发的世界观条目）**：
   - 一组条目，每条有 `keywords` + `content`（设定/背景/人物关系/地点描述）。
   - 请求前扫描最近对话，命中关键词就把对应条目追加到 post-history 指令后面（和 P1 的注入位置一致）。
   - 例：
     ```
     keywords: ["列克星敦", "姐姐"]
     content: 列克星敦是企业的姐姐，目前负责港区外联与后勤协调。
     ```
   - 存 `AppDataLocation/lorebook/*.json`，可让用户在设置页编辑。

2. **故事状态文件**：
   - 一个小的结构化状态，记录「当前进行到哪」：
     ```json
     {
       "location": "港区宿舍",
       "time": "傍晚",
       "current_event": "准备周六的联合演习",
       "pending_promises": ["答应过要一起看日落"]
     }
     ```
   - 每轮结束后由 LLM 更新（增量，不重写整段历史）。
   - 注入方式同 P3：压缩成一小段放进请求。

### 与 P3 的关系

- P3 记「事实」（静态属性、偏好），P4 记「剧情」（动态位置、事件推进）。可以共用同一套「抽取 → 存 JSON → 注入」管线，只是抽取的目标 schema 不同。
- Lorebook 是「命中即注入」的静态知识；故事状态是「持续演进」的动态知识。

### 不做什么（当前）

- 不做完整的「世界模拟器」或多角色管理——本阶段只需要企业这一个角色的沉浸感。

---

## 备注

- 注入点的统一：P3/P4 落地时，所有「记忆/设定/剧情」片段都应走与 P1 相同的注入位置（历史之后、生成之前），避免散落各处难维护。
- 省 token：长对话下必须做选择（只注入相关片段），不能无脑全量注入。
